    - Test: POST /sourcing/leads/:id/draft-outreach creates outreach draft

  </behavior>
  <action>
    NOTE: This plan runs in parallel with Plan 02 (Wave 2). All references to
    Plan 02 artifacts (sourcingApprovalService, sourcingOutreachService) MUST use
    lazy runtime imports inside handler functions — NO top-level import statements
    for Plan 02 files. Tests use static analysis (no runtime imports needed).

    1. Create server/sourcingRoutes.ts:
       - Import Router from 'express'
       - Export const sourcingRouter = Router()
       - All handlers use lazy imports for services and pool (consistent pattern)
       - CRITICAL: Use `const { approveOutreach } = await import(...)` inside handlers, NOT top-level imports for Plan 02 artifacts

       PIPELINE ENDPOINTS:

       GET /sourcing/leads
       - Query proactive_leads with optional filters: ?source=, ?search= (address/ownerName ILIKE), ?status=
       - For pipeline view, group by status: count per stage + lead array per stage
       - Response: { stages: { new: { count, leads }, scored: { count, leads }, ... }, total }
       - Pipeline stages map to proactive_leads.status: new, researching, ready_to_contact, contacted, responded, meeting_scheduled, valuation_booked, instructed
       - JOIN propensity_scores for score display
       - ORDER BY leadScore DESC within each stage

       GET /sourcing/leads/:id
       - Query proactive_leads by id
       - JOIN lead_contact_history for outreach history
       - JOIN propensity_scores for scoring details
       - Response: { lead, contactHistory, propensityScore }

       POST /sourcing/leads/:id/draft-outreach
       - Body: { sequenceStep? }
       - Lazy import draftOutreach from sourcingOutreachService
       - Call draftOutreach(leadId, sequenceStep)
       - Return draft result

       APPROVAL ENDPOINTS:

       GET /sourcing/approvals
       - Lazy import getPendingApprovals from sourcingApprovalService
       - Return pending approvals

       POST /sourcing/approvals/:id/approve
       - Lazy import approveOutreach
       - Call approveOutreach(contactHistoryId, req.user.id)
       - Return { success: true }

       POST /sourcing/approvals/:id/reject
       - Body: { reason? }
       - Lazy import rejectOutreach
       - Call rejectOutreach(contactHistoryId, req.user.id, reason)
       - Return { success: true }

       PUT /sourcing/approvals/:id/edit
       - Body: { content, subject? }
       - Lazy import editOutreachDraft
       - Call editOutreachDraft(contactHistoryId, content, subject)
       - Return { success: true }

       CAMPAIGN ENDPOINTS:

       GET /sourcing/campaigns
       - Query lead_monitoring_configs ORDER BY created_at DESC
       - Return array of campaigns

       POST /sourcing/campaigns
       - Body: { name, monitorType, description?, postcodeAreas, minPrice?, maxPrice?, propertyTypes?, frequency, config?, isEnabled? }
       - Insert into lead_monitoring_configs
       - Set config.followUpSequence to default if not provided
       - Return created campaign

       PUT /sourcing/campaigns/:id
       - Body: partial campaign fields
       - Update lead_monitoring_configs by id
       - Return updated campaign

       DELETE /sourcing/campaigns/:id
       - Delete lead_monitoring_configs by id
       - Return { success: true }

       METRICS ENDPOINTS:

       GET /sourcing/metrics
       - Query aggregate counts from proactive_leads:
         * leadsSourcedThisMonth: COUNT WHERE created_at >= start of month
         * outreachSent: COUNT of lead_contact_history WHERE status='sent' AND created_at >= start of month
         * responseRate: (COUNT responded) / (COUNT sent) * 100
         * valuationsBooked: COUNT WHERE status='valuation_booked' AND updated_at >= start of month
       - Return { leadsSourcedThisMonth, outreachSent, responseRate, valuationsBooked }

       GET /sourcing/metrics/by-source
       - Query proactive_leads grouped by lead_source:
         * Per source: leadsFound, outreachSent, responses, responseRate, valuations, instructions, conversionRate
       - Return array of source metrics

       MANUAL ACTIONS:

       POST /sourcing/monitors/:type/run
       - Lazy import ProactiveLeadGenService
       - Call runMonitor(type)
       - Return { success: true, message: 'Monitor scan triggered' }
