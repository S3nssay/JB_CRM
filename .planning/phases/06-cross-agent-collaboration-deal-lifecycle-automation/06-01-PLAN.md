   - Define pipeline templates as const arrays (code-defined, not database-stored per user decision):
     - LETTINGS_AGREED_PIPELINE: right_to_rent (admin, no deps), ast_contract (admin, depends on right_to_rent), deposit_registration (admin, no deps), inventory_report (admin, no deps), welcome_message (pm, no deps), checkin_inspection (pm, no deps) -- 6 steps

     - LEASE_RENEWAL_PIPELINE: tenant_contact (lettings, no deps), generate_ast (admin, depends on tenant_contact), -- if not renewing, triggers tenancy_ending pipeline
     - SALE_AGREED_PIPELINE: sales_memorandum (admin, no deps), solicitor_notification (admin, no deps), compliance_checklist (admin, no deps), delist_rental (lettings, no deps, isOptional: true)
     - SALE_COLLAPSED_PIPELINE: relist_property (sales, no deps), notify_interested_buyers (sales, no deps), cancel_in_progress (admin, no deps)
   - Export PIPELINE_TEMPLATES map: { lettings_agreed, tenancy_ending, lease_renewal, sale_agreed, sale_collapsed } -> PipelineStep[]

   - dealPipelineService singleton:
     - initializePipeline(pipelineType: string, deal: Deal): Creates deal_step rows for all steps in the template. Sets timeoutAt = now + step.timeoutHours. Starts steps with no dependencies (sets status='in_progress', startedAt=now). Emits deal events for pipeline start.
     - advanceStep(dealId: number, stepId: string): Marks step completed (status='completed', completedAt=now). Finds dependent steps whose ALL dependencies are now completed. Starts those steps. If all steps completed/skipped, marks deal completed. Creates deal_event for each state change.
     - failStep(dealId: number, stepId: string, reason: string): Marks step failed. Pauses the deal. Creates deal_event. The originating agent is expected to collect missing info per user decision.
     - skipStep(dealId: number, stepId: string, userId: number): Staff override -- marks step skipped (isSkipped=true, overriddenBy, overriddenAt, overrideAction='skip'). Advances pipeline as if step completed.
     - completeStepManually(dealId: number, stepId: string, userId: number): Staff manually marks step complete. Advances pipeline.
     - checkTimeouts(): Queries deal_steps WHERE status='in_progress' AND timeoutAt < now AND escalatedAt IS NULL. For each: calls escalationService.escalateToStaff with deal context. Sets escalatedAt on the step. Creates deal_event for timeout. Schedule this via pg-boss repeating job every 15 minutes.

   - Register event subscribers on module load (lazy):
     - Subscribe to DEAL_EVENTS.STEP_COMPLETED -> check if downstream steps can start
     - Subscribe to DEAL_EVENTS.STEP_TIMED_OUT -> escalate via escalationService
