  <name>Task 1: Deal REST API Routes</name>
  <files>server/dealRoutes.ts, server/routes.ts, server/__tests__/dealRoutes.test.ts</files>
  <behavior>
    - Test: GET /api/crm/deals returns list of deals (filterable by status, dealType)
    - Test: GET /api/crm/deals/:id returns deal with steps and recent events
    - Test: POST /api/crm/deals/:id/pause sets deal to paused with reason, logged to audit
    - Test: POST /api/crm/deals/:id/resume unpauses deal
    - Test: POST /api/crm/deals/:id/cancel cancels deal with reason
    - Test: POST /api/crm/deals/:id/steps/:stepId/skip staff-skips a step and pipeline advances
    - Test: POST /api/crm/deals/:id/steps/:stepId/complete staff manually completes a step
    - Test: All staff override endpoints require authentication
    - Test: All staff actions create deal_events with actorType='staff'
  </behavior>
  <action>
1. Create server/dealRoutes.ts:
   - Import Express Router, dealService, dealPipelineService, auditLogger
   - Use requireAgent middleware on all routes (same pattern as crmRoutes.ts)

   Endpoints:
   - GET /deals -- list deals with optional query params: status, dealType, propertyId. Returns array with step summary counts (pending/in_progress/completed/failed).
   - GET /deals/:id -- single deal with full steps array and last 50 events. Include property address (join or separate query).
   - GET /deals/:id/events -- paginated deal events (query: limit, offset). For timeline rendering.
   - GET /deals/:id/steps -- all steps for deal with current status.
   - POST /deals/:id/pause -- body: { reason: string }. Calls dealService.updateDeal with pausedAt=now, pausedBy=req.user.id, pauseReason. Creates deal_event. Returns updated deal.
   - POST /deals/:id/resume -- Clears paused fields. Creates deal_event. Returns updated deal.
   - POST /deals/:id/cancel -- body: { reason: string }. Sets cancelledAt/cancelledBy/cancelReason. Cancels all pending/in_progress steps. Creates deal_event.
   - POST /deals/:id/steps/:stepId/skip -- Calls dealPipelineService.skipStep(dealId, stepId, req.user.id). Returns updated step.
   - POST /deals/:id/steps/:stepId/complete -- Calls dealPipelineService.completeStepManually(dealId, stepId, req.user.id). Returns updated step.

   All mutation endpoints follow pattern:
   ```
   try { ... res.json(result) } catch (error) { console.error(...); res.status(500).json({ error: '...' }) }
   ```

2. Mount in server/routes.ts:
   - Import dealRouter from './dealRoutes'
   - Add `app.use('/api/crm', dealRouter)` BEFORE the existing catch-all routes (same pattern as other sub-routers)

3. Create server/__tests__/dealRoutes.test.ts:
   - Mock dealService and dealPipelineService
   - Test each endpoint returns correct status codes and calls correct service methods
   - Test auth requirement (401 without user)
   - Test staff override endpoints create audit events
  </action>
  <verify>

  </verify>

</task>

  <files>server/dealRoutes.ts, server/__tests__/notificationSSE.test.ts</files>
  <behavior>
    - Test: GET /api/crm/notifications/stream returns SSE headers (text/event-stream, no-cache, keep-alive)
    - Test: pushNotification(userId, notification) writes SSE data to connected client
    - Test: Client disconnect removes connection from sseClients map
    - Test: Heartbeat sends comment every 30 seconds to keep connection alive
    - Test: GET /api/crm/notifications returns notification list for authenticated user
    - Test: POST /api/crm/notifications/:id/read marks notification as read
    - Test: POST /api/crm/notifications/read-all marks all as read
    - Test: GET /api/crm/notifications/unread-count returns count
  </behavior>
  <action>
1. Add SSE and notification REST endpoints to server/dealRoutes.ts:

   SSE infrastructure (module-level):
   - `const sseClients = new Map<number, Response>()` -- userId -> SSE response
   - `export function pushNotification(userId: number, notification: any)`: writes `data: ${JSON.stringify(notification)}\n\n` to client if connected
   - Heartbeat: setInterval every 30s iterating sseClients, writing `:\n\n` comment, catching write errors and cleaning up dead connections

   SSE endpoint:
   - GET /notifications/stream -- requireAgent, set headers (Content-Type: text/event-stream, Cache-Control: no-cache, Connection: keep-alive), store res in sseClients keyed by req.user.id, on 'close' event delete from map

   REST notification endpoints:
   - GET /notifications -- dealService.getNotifications(req.user.id, req.query.unreadOnly === 'true'). Returns array.
   - GET /notifications/unread-count -- dealService.getUnreadCount(req.user.id). Returns { count: number }.
   - POST /notifications/:id/read -- dealService.markNotificationRead(id). Returns { success: true }.
   - POST /notifications/read-all -- dealService.markAllNotificationsRead(req.user.id). Returns { success: true }.

2. Wire pushNotification into dealPipelineService:
   - When a deal_event is created that has a relevant staff member (property manager, assigned agent), call pushNotification and also persist via dealService.createNotification
   - Add a notifyDealStakeholders(dealId: number, event: DealEvent) helper that:
     - Looks up the deal's property to find property_manager_id and agent_id
     - Creates a notification for each relevant staff member
     - Calls pushNotification for real-time delivery

3. Create server/__tests__/notificationSSE.test.ts:

   - Test client cleanup on disconnect
   - Test notification REST endpoints return correct data
