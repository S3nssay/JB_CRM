<objective>
Build the arrears chasing agent with hard-coded compliance rules, vulnerability detection, and outbound contact capability.

Purpose: This is the core of Phase 5. The arrears agent contacts tenants in rent arrears via SMS/WhatsApp with strict compliance enforcement. The compliance guard is a standalone code module (NOT prompt instructions) that enforces: max 1 call + 1 message per 48 hours per tenant, no Sunday contact, no contact outside 09:00-20:00 UK time, auto-escalation after 3 unsuccessful contacts, and immediate escalation on vulnerability detection. Every contact attempt is audit-logged.

Output: Working ArrearsComplianceGuard, VulnerabilityDetector, and arrearsAgent. Compliance rules are enforced at the code level — the LLM cannot override them.
</objective>

       - Import db from db.ts

       - Interface `ContactCheckResult`:
         * allowed: boolean
         * reason: string | null
         * nextAllowedAt: Date | null

       - `canContact(tenantId: number, contactType: 'sms' | 'whatsapp' | 'phone_call' | 'email'): Promise<ContactCheckResult>`:
         * Check 1: Opt-out — query contact_identity where contactId=tenantId, contactType='tenant', optedOut=true. If found → denied
         * Check 2: Vulnerability — query arrears where tenantId matches and status='active'. If notes contains 'VULNERABILITY_DETECTED' → denied
         * Check 3: Time-of-day — get current UK time (use Intl.DateTimeFormat with 'Europe/London' timezone). If hour < 9 or hour >= 20 → denied with nextAllowedAt = next 09:00
         * Check 4: Sunday — if day is Sunday → denied with nextAllowedAt = Monday 09:00
         * Check 5: Contact limit — count dunning_actions for this tenant's active arrears where status='sent'. If count >= 3 → denied (escalation required)
         * Check 6: 48-hour window — for message types (sms/whatsapp/email), check dunning_actions where channel IN ('sms','whatsapp','email') AND sentAt > now-48h for the tenant's arrears. For phone_call, check action_type='phone_call' AND sentAt > now-48h. If found → denied with nextAllowedAt = sentAt + 48h
         * All checks pass → { allowed: true, reason: null, nextAllowedAt: null }
         * Order matters: opt-out and vulnerability checks first (permanent blocks), then time-based, then frequency

       - `logContactAttempt(arrearsId: number, actionType: string, channel: string, status: 'sent' | 'blocked', notes?: string): Promise<void>`:
         * Insert into dunning_actions table
         * Update arrears.lastReminderSent if status='sent'

       - `getContactHistory(tenantId: number): Promise<DunningAction[]>`:
         * Return all dunning_actions for the tenant's active arrears, ordered by created_at desc

       - Export singleton `arrearsComplianceGuard` and class `ArrearsComplianceGuard`
