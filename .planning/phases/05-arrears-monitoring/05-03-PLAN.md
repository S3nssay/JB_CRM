<objective>
Build the agent monitoring dashboard — a React page where staff can view all agent conversations, review escalations, track per-agent metrics, and browse the audit log.

Purpose: This gives staff visibility into what the AI agents are doing across all channels. They can review conversation threads, action the escalation queue, monitor agent performance, and audit every action taken. This is critical for compliance (demonstrating proportionate arrears contact) and operational oversight.

Output: Working dashboard at /crm/agent-monitoring with 4 tabs (Conversations, Escalations, Metrics, Audit Log), backed by API endpoints querying existing tables. No new schema required — all data comes from conversations, messages, and agent_audit_log tables.
</objective>

  <behavior>
    - GET /api/crm/agent-monitoring/conversations returns paginated agent conversations with filters (channel, agentType, dateFrom, dateTo, status)
    - GET /api/crm/agent-monitoring/conversations/:id/thread returns all messages and audit log entries for a conversation, ordered by timestamp
    - GET /api/crm/agent-monitoring/escalations returns conversations where priority='urgent' and status='open', with escalation audit entries
    - GET /api/crm/agent-monitoring/metrics returns aggregated per-agent metrics (conversation count, escalation count, avg response time, tool call counts) for a date range
    - GET /api/crm/agent-monitoring/audit-log returns paginated agent_audit_log entries with filters (agentType, action, dateFrom, dateTo)
  </behavior>
  <action>
    1. Add monitoring endpoints to `server/crmRoutes.ts`:
       - Place all endpoints under the `/agent-monitoring/` path prefix
       - Import conversations, messages, agentAuditLog from schema
       - Import sql, eq, and, gte, lte, desc, count, avg from drizzle-orm

       - `GET /agent-monitoring/conversations`:
         * Query params: page (default 1), limit (default 20), channel, agentType, dateFrom, dateTo, status
         * Query conversations where source='ai_agent'
         * Apply filters: channel matches lastChannel, agentType matches, createdAt between dateFrom/dateTo, status matches
         * Order by lastMessageAt desc
         * Return { conversations: [...], total, page, limit }

       - `GET /agent-monitoring/conversations/:id/thread`:
         * Query messages where conversationId matches, order by createdAt asc
         * Query agentAuditLog where conversationId matches, order by createdAt asc
         * Merge and sort by timestamp into a unified timeline
         * Each entry has { type: 'message' | 'audit', timestamp, data: {...} }
         * Return { conversation: {...}, timeline: [...] }

       - `GET /agent-monitoring/escalations`:
         * Query conversations where priority IN ('urgent', 'high') AND status='open' AND source='ai_agent'
         * For each: get the latest audit log entry with action='escalate' to extract reason and assignee
         * Calculate timeWaiting = now - escalation timestamp
         * Order by timeWaiting desc (longest waiting first)
         * Return { escalations: [...], count }

       - `GET /agent-monitoring/metrics`:
         * Query params: dateFrom, dateTo (default: last 7 days)
         * Aggregate from agentAuditLog grouped by agentType:
           - conversationCount: COUNT(DISTINCT conversationId)
           - totalActions: COUNT(*)
           - escalationCount: COUNT(*) WHERE action='escalate'
           - avgDurationMs: AVG(durationMs) WHERE action='respond'
           - toolCallCount: COUNT(*) WHERE action='tool_call'
         * Also compute top tool usage: GROUP BY toolName, COUNT(*), order desc, limit 10
         * Return { agents: [...], topTools: [...], period: { from, to } }

       - `GET /agent-monitoring/audit-log`:
         * Query params: page (default 1), limit (default 50), agentType, action, dateFrom, dateTo
         * Query agentAuditLog with filters
         * Order by createdAt desc
         * Return { entries: [...], total, page, limit }

       - Test "all endpoints require authentication" (if auth middleware applied)
