<objective>
Voice tool-call webhook endpoints: Vapi tool calls hitting same Tool Registry from Phase 1, pre-call context loading for known callers.

Purpose: Bridges Vapi's external voice AI platform to the CRM's internal Tool Registry. When a voice assistant needs to search properties, book a viewing, or create a lead during a live call, Vapi POSTs a tool-call webhook to our server. This plan creates the Express endpoint that receives those calls, executes them via the existing ToolRegistry, and returns results in Vapi's required format. Also loads pre-call context so the voice agent knows who's calling.

Output: Working webhook endpoint at `/api/voice/vapi-webhook` that handles tool-calls and assistant-request events, plus pre-call context loading for known callers.
</objective>

    1. Create `server/agents/voice/vapiWebhooks.ts`:
       - Import: Router from express, toolRegistry, auditLogger, types from voice/types.ts
       - Create Express Router

       - **Middleware: Webhook authentication**
         * Read `VAPI_SERVER_SECRET` from process.env
         * On every request, check `req.headers['x-vapi-secret']` matches VAPI_SERVER_SECRET
         * If no VAPI_SERVER_SECRET is configured (dev mode), skip auth check and log a warning
         * If secret mismatch, return 401 `{ error: 'Unauthorized' }`

       - **POST `/vapi-webhook`** — Main server URL endpoint:
         * Parse `req.body.message.type` to determine event type
         * Switch on type:

         * Case `'tool-calls'`:
           - Extract `toolCallList` from `req.body.message`
           - Extract caller phone from `req.body.message.call?.customer?.number`
           - Extract call ID from `req.body.message.call?.id`
           - For each tool call in toolCallList:
             a. Parse `function.arguments` from JSON string to object
             b. Determine agentType from the assistant name (map: receptionist -> supervisor, Sales -> sales, Lettings -> rental, Admin -> office_admin)
             c. Build ToolContext: `{ agentType, conversationId: null, contactId: null, channel: 'phone' }`
             d. Check `toolRegistry.hasTool(function.name)`:
               - If yes: `const result = await toolRegistry.invoke(function.name, parsedArgs, context)`
               - If no: result = `{ output: 'Unknown tool' }`
             e. Build result: `{ toolCallId: toolCall.id, result: typeof result.output === 'string' ? result.output : JSON.stringify(result.output) }`
           - Wrap all results in try/catch. On error, result string = `Error: ${error.message}`
           - Return `res.status(200).json({ results })` — ALWAYS 200 per Vapi requirement

         * Case `'assistant-request'`:
           - Return `res.status(200).json({})` — placeholder, Plan 03-03 adds context loading

         * Case `'end-of-call-report'`:
           - Return `res.status(200).json({})` — placeholder, Plan 03-03 adds transcript processing

         * Case `'hang'`:
           - Log call end event
           - Return `res.status(200).json({})`

         * Default:
           - Log unhandled event type
           - Return `res.status(200).json({})`

    - loadCallerContext(phoneNumber) for a known landlord returns { contactName, contactType: 'landlord', recentSummary }
    - loadCallerContext(phoneNumber) for an unknown caller returns null (graceful degradation)
    - assistant-request webhook with known caller phone number returns dynamic assistant override with context injected into system prompt
    - assistant-request webhook with unknown caller returns empty response (use default config)
  </behavior>
  <action>
    1. Create `server/agents/voice/contextLoader.ts`:
       - Import contactResolver, conversationStore, db, pool
       - Define `CallerContext` interface:
         ```
         { contactName: string | null; contactType: string; contactId: number; recentSummary: string | null; conversationId: number | null }
         ```

       - `async function loadCallerContext(phoneNumber: string): Promise<CallerContext | null>`:
         a. Use `contactResolver.resolve(phoneNumber, 'phone')` to identify caller
         b. If contactId === 0 (unknown): return null
         c. Look up contact name based on contactType:
            - If 'tenant': query tenant table by id for name
            - If 'landlord': query landlords table by id for name
            - If 'lead': query leads table by id for name
         d. Use `conversationStore.findOrCreateConversation(contact, 'phone')` to find existing conversation
         e. If conversation exists and is not new:
            - Load last 5 messages via `conversationStore.getConversationHistory(conversationId, 5)`
            - Build a brief summary from last messages (last 2-3 message previews, max 200 chars)
         f. Return `{ contactName, contactType, contactId: contact.contactId, recentSummary, conversationId }`

       - Export `loadCallerContext`

    2. Update `server/agents/voice/vapiWebhooks.ts`:
       - Import `loadCallerContext` from contextLoader
       - In the `'assistant-request'` case handler:
         a. Extract caller phone from `req.body.message.call?.customer?.number`
         b. If phone exists: call `loadCallerContext(phone)`
         c. If context found:
            - Build a context injection string:
              ```
              `\n\nCALLER CONTEXT: The caller is ${context.contactName} (${context.contactType}). ${context.recentSummary ? 'Recent interaction: ' + context.recentSummary : 'No recent interaction history.'}`
              ```
            - Return response with assistant override that appends context to instructions:
              ```json
              { "assistant": { "instructionsOverride": baseInstructions + contextInjection } }
              ```
            - Actually, Vapi assistant-request can return a full or partial assistant config. The simplest approach: return empty response and let Vapi use the pre-configured assistant. Instead, use tool-calls to fetch context dynamically.
            - REVISED approach: Do NOT override assistant config. Instead, store the resolved context in a module-level Map keyed by call ID. When tool-calls come in, look up the stored context to populate the ToolContext with conversationId and contactId.
         d. Update Map: `activeCallContexts.set(callId, context)`
         e. Return `res.status(200).json({})`

       - In the `'tool-calls'` case handler:
         a. After extracting call ID, look up `activeCallContexts.get(callId)`
         b. If found: use context.conversationId and context.contactId in the ToolContext
         c. This allows Tool Registry calls to be associated with the correct conversation and contact

       - In the `'hang'` case handler:
         a. Clean up: `activeCallContexts.delete(callId)`

       - In the `'end-of-call-report'` case handler:
         a. Clean up: `activeCallContexts.delete(callId)` (belt and suspenders with hang)

    3. Update tests in `tests/voice/vapiWebhooks.test.ts`:
       - Mock contactResolver.resolve to return known contact for specific phone numbers
       - Mock conversationStore for conversation lookup
       - Test: assistant-request with known caller phone -> stores context in activeCallContexts
       - Test: subsequent tool-call for same call ID uses stored conversationId and contactId in ToolContext
       - Test: assistant-request with unknown caller -> no context stored, tool calls use null conversationId
       - Test: hang event cleans up activeCallContexts
       - Test: loadCallerContext for known tenant -> returns name and type
       - Test: loadCallerContext for unknown number -> returns null
  </action>
