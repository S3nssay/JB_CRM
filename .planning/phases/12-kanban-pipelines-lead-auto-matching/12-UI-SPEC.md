## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, card inner gaps (p-2) |
| md | 16px | Default element spacing, card padding (p-4) |
| lg | 24px | Section padding, main content padding (p-6) |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Kanban column min-width: 280px (established pattern from PropertyPipeline.tsx)
- Kanban column header padding: 8px vertical, 12px horizontal (py-2 px-3)
- Pipeline stats grid gap: 8px (gap-2, matching existing pattern)
- Kanban card internal spacing: 8px (p-2 for card gaps, p-3 for card content)
- Filter bar padding: 16px (p-4)

```

+--------------------------------------------------+
| Filter Bar: [Search] [Type Filter] [Other Filter] |
+--------------------------------------------------+
| Stats Row: [Stage1: N] [Stage2: N] ... [StageN: N]|
+--------------------------------------------------+

|  [Column1]  [Column2]  [Column3]  ...  [ColumnN] |
```

- Header height: 64px (h-16)

- Column header: colored background with white text, rounded top corners
- Column well: `bg-gray-100`, rounded bottom corners, 8px padding, min-height 400px
- Cards: white, 12px padding, 8px vertical spacing between cards

## Interaction Contracts

### Stage Advancement (Kanban Cards)
- Each card shows an "Advance to {next stage}" button (ArrowRight icon + label)
- Click triggers PATCH request to update pipeline_stage
- Optimistic update moves card to next column immediately
- On error: revert card position, show destructive toast
- Terminal actions (Fallen Through, Withdrawn) available from dropdown or secondary button on any active-stage card

### Lead Auto-Match Trigger
- No direct UI trigger -- matching runs server-side when property status reaches "listed"
- Matches appear in the Lead Matches page as new pending items
- Toast notification on pipeline page: "{N} leads matched" after advancing to Listed

### Match Approval Flow
- Staff clicks "Approve & Send Details" on a match card
- Confirmation dialog: "Send property details to {lead name} via {channel}?"
- On confirm: PATCH match status to "approved", system sends details asynchronously
- Card status updates to "Sent" after delivery
- Staff can also click "Dismiss" to reject without sending

### Landlord Lead Type Filter
- Select dropdown in filter bar: "All Owners", "Letting Owners", "Selling Owners"
- Maps to API query parameter: `inquiryType=letting` or `inquiryType=selling` or omitted for all
- Filter change triggers TanStack Query refetch with new query key
