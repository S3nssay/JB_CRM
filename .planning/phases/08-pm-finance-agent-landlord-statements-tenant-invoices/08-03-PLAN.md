<task type="auto">
  <name>Task 1: Statement approval and send API endpoints</name>
  <files>server/financeRoutes.ts</files>
  <action>
    Read server/financeRoutes.ts first. Add the following endpoints to the existing finance router (do NOT create a new router file):

    1. `GET /api/crm/finance/statements/pending` -- Returns all landlord_statement records with status='draft', joined with landlord name and property address. Include attention_needed flag. Order by created_at desc. Include statement_line_items for each. Paginated (page/limit query params, default 20).

    2. `POST /api/crm/finance/statements/:id/approve` -- Updates statement status from 'draft' to 'approved'. Returns 400 if not in draft status. Logs via auditLogger.

    3. `POST /api/crm/finance/statements/:id/send` -- Only works on 'approved' statements. Steps:
       a. Load statement with line items, landlord email, property address
       b. Generate PDF via pdfService.generateStatementPDF()
       c. Save PDF buffer to uploads/ directory as `statements/STMT-YYYYMM-{propertyId}.pdf`
       d. Update statement.pdfUrl to the file path
       e. Send email to landlord with PDF attachment via emailService.sendEmail()
       f. Update status to 'sent', set sentAt to now
       g. Log via auditLogger
       Returns 400 if not in approved status.

    4. `POST /api/crm/finance/statements/:id/reject` -- Updates statement status back to... actually, reject should delete or flag. Implement as: delete statement and its line items (it was auto-generated, staff can re-trigger). Log reason via auditLogger.

    5. `POST /api/crm/finance/statements/generate` -- Manual trigger endpoint. Accepts { year, month } in body. Calls generateMonthlyStatements(year, month). Returns { created, attentionNeeded }. Requires auth.

    6. `POST /api/crm/finance/invoices/generate` -- Manual trigger endpoint. Calls generateMonthlyInvoices(new Date()). Returns { created, sent }. Requires auth.

    7. `GET /api/crm/finance/invoices` -- List invoices with filters: tenantId, propertyId, status, invoiceType. Paginated. Joins tenant name and property address. Order by due_date desc.

    All endpoints use raw SQL (pool.query) consistent with existing financeRoutes patterns. All require authentication (req.isAuthenticated() check at router level or per-route).
  </action>

  </verify>
  <done>7 new endpoints added to financeRoutes.ts; statement approval transitions draft->approved->sent; manual trigger endpoints work; invoice listing with filters available</done>
