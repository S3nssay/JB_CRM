<objective>
Build the work order follow-up and completion verification system: automated pg-boss scheduled follow-ups to contractors and tenants, audit logging of all verification attempts, and escalation on non-response.

Purpose: After a work order is dispatched, the PM agent needs to follow up to ensure the work is actually completed. This plan adds scheduled follow-ups that check with both the contractor (is work progressing?) and the tenant (is the issue resolved?), logging every attempt and escalating to staff when follow-ups go unanswered.

Output: Fully automated work order follow-up lifecycle with configurable intervals, audit trail, and escalation.
</objective>

  <name>Task 1: Work order follow-up service with pg-boss workers</name>
  <files>

  <behavior>
    - scheduleFollowups(workOrderId, urgency) queues: contractor-followup at interval based on urgency, tenant-followup at same interval, completion-check at scheduledEnd date
    - Intervals: emergency=24h, urgent=48h, routine=72h, low=96h
    - wo-contractor-followup worker: sends "Checking on work order WO-XXXX at {address}. Is the work progressing as planned?" to contractor, logs attempt via auditLogger
    - wo-tenant-followup worker: sends "Our contractor should have attended to the {issue} at your property. Has the issue been resolved?" to tenant, logs attempt via auditLogger
    - wo-completion-check worker: checks work order status; if not 'completed', sends follow-up to both and schedules another check
    - After 2 unanswered follow-ups per party, escalates to staff with full work order context
    - Every follow-up attempt logs: workOrderId, ticketId, type (contractor/tenant/completion), attemptNumber, timestamp
  </behavior>
  <action>
    1. Create `server/agents/services/workOrderFollowup.ts`:
       - Import PgBoss, messageSender, auditLogger, escalationService, db
       - Import workOrders, maintenanceTickets, contractors, tenant, properties from schema

       - Define follow-up intervals:
         ```typescript
         const FOLLOWUP_INTERVALS: Record<string, number> = {
           emergency: 24 * 60 * 60,   // 24 hours in seconds
           urgent: 48 * 60 * 60,      // 48 hours
           routine: 72 * 60 * 60,     // 72 hours
           low: 96 * 60 * 60,         // 96 hours
         };
         const MAX_FOLLOWUP_ATTEMPTS = 2;
         ```

       - Export interface `FollowupJobData`:
         ```typescript
         { workOrderId: number; ticketId: number; contractorId: number; tenantId: number; propertyId: number; urgency: string; attemptNumber: number; }
         ```

       - Export class `WorkOrderFollowupService`:

         * `async scheduleFollowups(workOrderId: number, urgency: string): Promise<void>`:
           1. Look up work order to get ticketId, contractorId, scheduledEnd
           2. Look up ticket to get tenantId, propertyId
           3. Calculate interval from urgency
           4. Queue pg-boss jobs:
              - `wo-contractor-followup`: startAfter = interval, data = { workOrderId, ticketId, contractorId, tenantId, propertyId, urgency, attemptNumber: 1 }
              - `wo-tenant-followup`: startAfter = interval, data = same
              - `wo-completion-check`: startAfter = scheduledEnd time (if set), data = same

         * Worker handler `handleContractorFollowup(job: PgBoss.Job<FollowupJobData>)`:
           1. Check if work order still active (not completed/cancelled)
           2. If completed/cancelled: skip, log skipped
           3. Look up contractor contact info + work order details + property address
           4. Send message: "Hi {contractorName}, John Barclay Estate Agents checking on work order {woNumber} at {address}. Please confirm: Is the work progressing as planned? Reply with a status update."
           5. Log via auditLogger: { agentType: 'maintenance', toolName: 'wo-contractor-followup', toolInput: { workOrderId, attemptNumber }, toolOutput: { messageSent: true }, channel: 'system' }
           6. If attemptNumber >= MAX_FOLLOWUP_ATTEMPTS: escalate to staff
           7. Else: schedule next attempt at +interval with attemptNumber + 1

         * Worker handler `handleTenantFollowup(job: PgBoss.Job<FollowupJobData>)`:
           1. Check if work order still active
           2. Look up tenant contact info + ticket details + property address
           3. Send message: "Hi {tenantName}, this is John Barclay Estate Agents. Our contractor was scheduled to attend to the {ticketTitle} at your property. Has the issue been resolved? Please let us know."
           4. Log via auditLogger
           5. If attemptNumber >= MAX_FOLLOWUP_ATTEMPTS: escalate to staff
           6. Else: schedule next attempt

         * Worker handler `handleCompletionCheck(job: PgBoss.Job<FollowupJobData>)`:
           1. Check work order status
           2. If 'completed': log completion verified, done
           3. If not completed:
              - Send follow-up to contractor: "Work order {woNumber} was due for completion. Please provide a status update."
              - Send follow-up to tenant: "The scheduled maintenance at your property should now be complete. Has the issue been resolved?"
              - Schedule another completion check at +24h (max 3 checks)
              - If 3 checks and still not completed: escalate to staff as overdue

       - Export function `registerWorkOrderFollowupWorkers(boss: PgBoss)`:
         * `boss.work('wo-contractor-followup', handler)`
         * `boss.work('wo-tenant-followup', handler)`
         * `boss.work('wo-completion-check', handler)`

       - Export singleton `workOrderFollowupService`

    2. Write tests in `tests/agents/workOrderFollowup.test.ts`:
       - Mock pg-boss, messageSender, auditLogger, db
       - Test scheduleFollowups: verify 3 jobs queued with correct intervals for 'emergency' urgency (24h)
       - Test scheduleFollowups: verify 3 jobs queued with correct intervals for 'routine' urgency (72h)
       - Test handleContractorFollowup: verify message sent to contractor, auditLogger called with correct params
       - Test handleContractorFollowup: verify completed work order is skipped
       - Test handleContractorFollowup: verify escalation after MAX_FOLLOWUP_ATTEMPTS
       - Test handleTenantFollowup: verify message sent to tenant, auditLogger called
       - Test handleTenantFollowup: verify escalation after MAX_FOLLOWUP_ATTEMPTS
       - Test handleCompletionCheck: verify completed status is logged and no further action
       - Test handleCompletionCheck: verify overdue work order triggers follow-ups to both parties
       - Test audit log entries include: workOrderId, ticketId, attemptNumber, followUpType
