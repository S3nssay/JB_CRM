<objective>
Build the contractor dispatch pipeline: contractor search and selection, quote request, landlord approval workflow (with emergency bypass), and work order creation.

Purpose: After the PM agent creates a maintenance ticket (Plan 01), it needs to find the right contractor, get a quote, obtain landlord approval (non-emergency) or bypass approval (emergency), create a formal work order, and notify the contractor. This plan builds all four tools and the landlord approval service.

Output: PM agent can dispatch contractors end-to-end, with landlord approval for non-emergency work and immediate dispatch for emergencies.
</objective>

    1. Create `server/agents/tools/definitions/searchContractors.ts`:
       - InputSchema: z.object({ category: z.string(), postcode: z.string().optional(), emergency: z.boolean().optional() })
       - OutputSchema: z.object({ contractors: z.array(z.object({ id, companyName, contactName, phone, email, specializations, rating, responseTime, callOutFee, hourlyRate, preferredContractor, availableEmergency })), count: z.number() })
       - Execute:
         1. Query contractors table WHERE isActive = true
         2. Filter by specializations array contains category (use SQL: category = ANY(specializations) or ilike matching)
         3. If postcode provided: filter by serviceAreas overlap (first 2-4 chars of postcode match any service area entry)

         5. Sort: preferredContractor DESC, rating DESC NULLS LAST, responseTime ASC (map text to numeric: '1 hour'=1, '4 hours'=4, '24 hours'=24, '48 hours'=48)
         6. Limit to 5 results
       - Permissions: ['maintenance', 'supervisor']
       - Tier: 'autonomous'

    2. Create `server/agents/tools/definitions/requestContractorQuote.ts`:
       - InputSchema: z.object({ ticketId: z.number(), contractorId: z.number(), jobDescription: z.string(), propertyAddress: z.string(), urgencyLevel: z.string().optional() })
       - OutputSchema: z.object({ quoteId: z.number(), status: z.string(), contractorContacted: z.boolean() })
       - Execute:
         1. Look up contractor record to get contact details and preferred channel
         2. Insert into contractorQuotes: ticketId, contractorId, status 'pending', sentAt: now()
         3. Compose message: "John Barclay Estate Agents - Maintenance Request\n\nTicket: MT-{ticketId}\nProperty: {propertyAddress}\nUrgency: {urgencyLevel}\n\nFault: {jobDescription}\n\nPlease reply with your quote, estimated duration, and earliest availability."
         4. Send via messageSender: if contractor has phone -> WhatsApp (preferred), fallback SMS; if email only -> email
         5. Return quoteId, status, contractorContacted success/failure
       - Permissions: ['maintenance', 'supervisor']
       - Tier: 'autonomous'

    3. Register both tools in `server/agents/tools/registry.ts`

    4. Add SDK wrappers in `server/agents/sdk/tools.ts`:
       - searchContractorsTool: wrapRegistryTool with z4 schema
       - requestContractorQuoteTool: wrapRegistryTool with z4 schema

    - create_work_order({ ticketId: 1, contractorId: 5, scope: "Replace boiler thermostat", scheduledStart: "2026-03-25T09:00:00Z", quotedAmount: 25000 }) creates work order with generated WO-YYYYMMDD-XXXX number

    1. Create `server/agents/services/landlordApproval.ts`:
       - Export class `LandlordApprovalService`:
         * `requestApproval(params: { ticketId, landlordId, quoteAmount, contractorName, faultDescription, isEmergency })`:
           - Look up landlord from landlords table (name, email, mobile, phone)
           - If isEmergency:
             * Update contractor_quote status to 'approved'
             * Set approvalNotes: 'Emergency auto-approved'
             * Send NOTIFICATION to landlord: "Emergency maintenance at {property}: {fault}. Contractor {name} dispatched immediately. Quoted: {amount}. We will update you on completion."
             * Log via auditLogger: emergency bypass with reasoning
             * Return { status: 'auto_approved', reason: 'Emergency: landlord approval bypassed' }
           - If NOT emergency:
             * Send APPROVAL REQUEST to landlord: "Maintenance request at {property}:\n\nFault: {description}\nContractor: {name}\nQuoted amount: {amount}\nEstimated duration: {duration}\n\nReply APPROVE to proceed or REJECT to decline."
             * Return { status: 'pending', message: 'Approval request sent to landlord' }
           - Channel: landlord mobile -> WhatsApp (preferred), SMS fallback; email as additional
         * `handleApprovalResponse(landlordId, response: 'approve' | 'reject', ticketId?)`:
           - If approve: update contractor_quote status to 'approved', set approvedAt
           - If reject: update to 'rejected', escalate to staff for re-selection
       - Export singleton `landlordApprovalService`

    2. Create `server/agents/tools/definitions/requestLandlordApproval.ts`:
       - InputSchema: z.object({ ticketId, landlordId, quoteAmount (in pence), contractorName, faultDescription, isEmergency: z.boolean() })
       - OutputSchema: z.object({ status: z.string(), reason: z.string().optional(), landlordContacted: z.boolean() })
       - Execute: delegate to landlordApprovalService.requestApproval()
       - Permissions: ['maintenance', 'supervisor']

    3. Create `server/agents/tools/definitions/createWorkOrder.ts`:

       - OutputSchema: z.object({ workOrderId: z.number(), workOrderNumber: z.string(), status: z.string() })

         2. Insert into workOrders table
         3. Update maintenance ticket status to 'assigned', set assignedContractorId
         4. Look up contractor contact details
         5. Send work order confirmation to contractor via messageSender: "Work Order {WO-number}\nProperty: {address}\nScope: {scope}\nScheduled: {date}\n\nPlease confirm attendance."
         6. Return workOrderId, workOrderNumber, status
       - Permissions: ['maintenance', 'supervisor']
