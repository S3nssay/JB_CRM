  <name>Task 1: Create portfolio monitoring service with compliance and health cron jobs</name>
  <files>server/services/portfolioMonitorService.ts, server/__tests__/portfolioMonitor.test.ts</files>
  <action>
Create `server/services/portfolioMonitorService.ts` following the established pg-boss lazy init pattern from `server/agents/services/workOrderFollowup.ts`:

1. Lazy pg-boss init (module-level `let boss: PgBoss | null = null`, async getBoss function using process.env.DATABASE_URL).

2. `registerPortfolioMonitorJobs()` function that schedules and registers workers for:

   a. `pm:daily-compliance-check` -- Cron: `0 8 * * *` (8am daily)
      Worker logic:
      - Query property_certification (IMPORTANT: grep schema.ts for exact table name -- it may be `property_certificate` not `property_certification`) for certs with expiry_date between CURRENT_DATE and CURRENT_DATE + INTERVAL '30 days' and status NOT IN ('renewed', 'superseded').
      - JOIN properties for address, JOIN landlords for landlord name and email.
      - Group results into `expired` (expiry_date < CURRENT_DATE) and `expiring_soon` (within 30 days).
      - If any results, send email via emailService to PM staff (use a configurable constant PM_STAFF_EMAIL or fall back to first admin user query).
      - Format email HTML with table listing: property address, certification type, expiry date, landlord name, urgency (expired vs expiring soon).
      - Also create a notification record in the notifications table for each expiring cert (notification type: 'compliance_alert').
      - Log to audit_log via auditLogger: action='compliance_check', agentType='system'.

   b. `pm:weekly-health-report` -- Cron: `0 9 * * 1` (9am Monday)
      Worker logic:
      - Query all managed properties (is_managed = true) with aggregated health data:
        - Compliance: count of expired/expiring certs per property
        - Maintenance: count of open tickets per property
        - Arrears: count of active cases and total outstanding per property
        - Vacancy: properties with no active tenancy
      - Calculate per-property health score (simple formula: start at 100, -20 per expired cert, -10 per expiring cert, -5 per open maintenance ticket, -15 per active arrears case, -25 if vacant).
      - Group by landlord for the summary.
      - Send formatted email to PM staff with landlord-grouped property health table.
      - Log to audit_log.

3. Export `registerPortfolioMonitorJobs` and also export the worker handler functions directly (`handleComplianceCheck`, `handleWeeklyHealthReport`) for unit testing without pg-boss.

Create `server/__tests__/portfolioMonitor.test.ts`:
- Test `handleComplianceCheck` with mocked pool.query returning expired/expiring certs -- verify it calls emailService.sendEmail with correct subject containing cert count.
- Test `handleComplianceCheck` with empty results -- verify no email sent.
- Test `handleWeeklyHealthReport` health score calculation: property with 1 expired cert + 2 open tickets = 100 - 20 - 10 = 70.
- Test `handleWeeklyHealthReport` groups properties by landlord correctly.
- Use vi.mock for pool.query and emailService.

IMPORTANT: Before writing SQL, grep schema.ts for exact table names: property_certificate vs property_certification, maintenance_request, arrears, properties, landlords, notifications, agent_audit_log.
